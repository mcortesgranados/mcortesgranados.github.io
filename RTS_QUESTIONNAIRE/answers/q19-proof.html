19. Other SPA frameworks and technologies

Answer as submitted

“Beyond Angular, I have delivered SPAs with React and Next.js, and worked with additional frameworks and micro-frontend techniques.”
Technical decision: expand. The submitted line names frameworks but not what the work consists of. This page is the separate, detailed version: it shows the same problem solved in React, Next.js and Vue, and the mobile and quality practices that stay constant across them.

Expanded answer

Beyond Angular, I work in React 19 (function components and hooks, context plus reducer for shared state, custom hooks, React.lazy/Suspense code splitting, error boundaries, React Router, and Jest/React Testing Library) and Next.js (app router, server and client components, SSG/ISR/SSR chosen per route, route handlers and image optimisation). I have also delivered with Vue 3 using the composition API and Pinia, built React Native screens for a mobile app that shares its domain package with the web client, and used micro-frontend techniques (module federation, web components/Angular Elements) to compose independently deployed front ends. Across all of them the constant is the engineering: accessibility, testing, bundle budgets and Core Web Vitals.

What transfers between frameworks

Rules I apply. Keep one source of truth and derive the rest; choose the rendering mode per route instead of per application; isolate failure in a boundary so one panel cannot blank the screen; split the bundle at the route; share the domain layer between web and mobile rather than reimplementing it; and hold every framework to the same accessibility, testing and performance budgets. Frameworks change; these constraints are what a team actually accumulates as experience.
