Have you worked with Angular? If yes, which versions?

AngularFrontendTypeScript

✅ Yes — Angular is one of my core front-end specialisations, used commercially for many years and currently at the Angular 17/18 level.

Technical detail

  • 🧱 AngularJS 1.x — the early MVC era: controllers, services, directives, two-way binding (useful context for migrations).
  • ⚙️ Angular 2+ through 11 — the modular TypeScript architecture: NgModules, components, Router with lazy loading, Http/HttpClient, RxJS streams, reactive forms, CLI-driven workspaces.
  • 🚀 Angular 17 / 18 — standalone components and APIs, new built-in control flow (@if, @for, @defer), signals and computed state, improved SSR/hydration, functional route guards and interceptors, strict typing in templates.

🛠️ What I actually build with it: feature-based folder architecture, route-level lazy loading, HTTP interceptors for tokens/errors, route guards, reactive forms with strong validation, custom directives and pipes, shared component libraries, Angular Material/CDK layouts, and state with NgRx or signal-based stores depending on complexity. 🧪 Quality: Jasmine/Karma unit tests and component tests wired to CI.

📌 Because I have lived through the framework's breaking changes, I know how to modernise older codebases (module → standalone, constructor DI → inject(), structural directives → new control flow) without destabilising the product.

🧾 CV evidence: 2025 CV: 'Advanced Angular 17/18 delivery with TypeScript, Router, HttpClient, RxJS, standalone and modular components, Jasmine/Karma testing'; FrontEnd Technologies: Angular (2023 CV); Chronology: Angular at Informatica y Buen Gobierno (2017-2019) and current role (2024-present).
