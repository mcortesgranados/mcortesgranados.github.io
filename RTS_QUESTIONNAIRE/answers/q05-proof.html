5. Cache strategies: Redis and Memcached

Answer as submitted

“Yes — Redis (cache-aside, TTL, pub/sub, cluster), plus Memcached and CDN caching.”
Technical decision: expand. The submitted line is accurate but compressed — the questionnaire caps each answer at one short line, so it names the technologies without the discipline behind them. This page is the separate, detailed version: it shows the exact operations, the implementation in code, and the rules that keep a cache from turning into a source of stale data.

Expanded answer

Yes. Redis is my primary distributed cache and I apply it with cache-aside reads, write-through updates and an explicit invalidation contract built on TTLs, jittered expirations and pub/sub invalidation. Memcached I use for the same key/value cache-aside model where a slim, non-persistent store is enough, and I add in-process IMemoryCache memoisation for the hot in-node layer plus HTTP/CDN caching at the edge.

How caching fits this answer

Why an invalidation contract comes first. A cache is only as good as its worst stale read. Before adding one I define how entries expire and how they are invalidated — TTL plus jitter for normal expiry, an event for explicit invalidation, and a single-flight lock for the moment of a miss — and then I measure hit ratio and p95 latency to confirm the cache actually earns its complexity.
