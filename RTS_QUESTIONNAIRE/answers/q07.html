Have you worked with IoC/DI containers such as Autofac, StructureMap, or similar frameworks?

DIArchitecture.NET

✅ Yes — Dependency Inversion is a default design principle in my code, implemented with several container technologies.

Technical detail

  • 🟪 .NET containers — the built-in Microsoft.Extensions.DependencyInjection host container as the baseline, plus experience with Autofac-style modular registration (module scanning, named/keyed registrations, decorators, lifetime scopes) and legacy StructureMap-family containers found in older enterprise codebases.
  • ☕ JVM containers — Spring Boot's IoC container with stereotype scanning, profiles, @Primary/@Qualifier, and constructor injection as the standard.
  • 🐍 Python/Node — FastAPI's Depends graph, Flask app factories with blueprints, and NestJS-style provider injection in TypeScript services.

🎛️ Concepts I apply consistently: correct lifetimes (singleton / scoped / transient) to avoid captive dependencies, composition roots kept at the application boundary, factory delegates for runtime parameters, decorators for cross-cutting concerns (logging, caching, retries, transactions) instead of scattered code, and interfaces that make unit testing trivial.

🧪 Result in practice: services that are testable in isolation, infrastructure that can be swapped (SQL ↔ in-memory, real HTTP client ↔ fake) without touching business logic, and registrations validated at startup so configuration errors fail fast rather than in production.

🧾 CV evidence: CV .NET Technologies line explicitly lists Dependency Injection; SOLID principles highlighted in the CV header; Spring Boot/Spring DI throughout the Java track; layered architecture and POC development competencies.
