15. Generative AI, agentic AI and MCP

Answer as submitted

“Yes — RAG, embeddings, Llama-3 QLoRA fine-tuning, agentic workflows and MCP servers.”
Technical decision: expand. The submitted line lists techniques but not the engineering that makes them dependable. This page is the separate, detailed version: it shows retrieval-grounded answering, the honest choice between fine-tuning and prompting, typed tool-calling for agents, and the guardrails and evals that keep a probabilistic system inside its bounds.

Expanded answer

Yes — this is active practice, not theory. I build RAG pipelines (chunking strategy, embeddings, vector search over pgvector/FAISS-style stores, citation-forced prompting, context-window and cost control), run fine-tuning only where it earns its keep (QLoRA adapters on Llama-3-class models for style and format, never to patch missing knowledge), wire agentic workflows through MCP with schema-typed tools and confirmation on anything that writes, and put guardrails around the model: PII redaction before the prompt, prompt-injection checks on retrieved text, tool allow-lists and strict output schemas. Every prompt or model change is measured against a golden set with regression checks, and cost and latency are tracked per request.

Why the system is built this way

Rules I apply. Retrieve before generating and force a citation; keep knowledge in the index rather than in the weights; expose capability to an agent only as schema-typed tools, with confirmation on write actions; minimise data before the prompt and validate whatever comes back; measure every change against a golden set; and track cost and latency per request. The model is a component with a probabilistic boundary — the surrounding engineering is what makes it usable in a business process.
