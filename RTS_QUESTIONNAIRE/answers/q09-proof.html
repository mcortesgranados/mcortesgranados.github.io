Expanded answer

Yes — more than 20 years with relational engines, and SQL Server and PostgreSQL as the two I know deepest. That covers T-SQL and PL/pgSQL development (stored procedures, functions, CTEs, window functions, JSONB modelling), schema and index design, execution-plan analysis, partitioning and statistics, ETL/ELT integration with SSIS and Airflow, plus the operational side: connection pooling, isolation choices, deadlock and blocking analysis, index maintenance, backup/restore and capacity planning. Oracle (9i–12c) and MySQL round out the same profile, and every hot query is validated against a real execution plan before release.

How the tuning loop is run

Rules I apply. Measure before touching anything; fix the query shape before adding an index; add an index only when the plan shows the seek it buys, and count its write cost; refresh statistics when estimates drift; choose isolation deliberately so readers do not block writers; and keep every business operation inside one explicit transaction with optimistic concurrency. The result is judged on p95 latency and logical reads, not on a single fast run on a warm cache.
