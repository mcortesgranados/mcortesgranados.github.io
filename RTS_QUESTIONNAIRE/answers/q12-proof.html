Answer as submitted

“Yes — AWS 6+ yrs (certified), Azure 4+ yrs (AZ-204/500) and GCP 3+ yrs (cloud architect).”
Technical decision: expand. The submitted line lists platforms and years but not what the work consists of. This page is the separate, detailed version: it shows the delivery path on the platform — code, pipeline identity, runtime choice, observability and cost — rather than a service inventory.

Expanded answer

Yes — AWS for 6+ years (certified across Solutions Architect Professional, Security, Database, DevOps Engineer Professional and Advanced Networking), Azure for 4+ years (AZ-204 and AZ-500) and GCP for 3+ years, plus Oracle Cloud exposure. The work covers the full path to production: VPC and network design, IAM and least privilege, containers on ECS/EKS and AKS, serverless for event-shaped work, managed data services (RDS, DynamoDB, DocumentDB, Neptune, Cosmos DB, Cloud SQL/BigQuery), messaging (SQS/SNS, EventBridge, Service Bus, Pub/Sub), infrastructure as code with CDK, CloudFormation and Terraform, and pipelines that authenticate through OIDC instead of long-lived keys.

What "cloud experience" means in practice

Rules I apply. Design the network and the identity model before the compute; keep every resource in code with the same stack promoted per environment; let the pipeline assume a role through OIDC instead of storing keys; put data services in private subnets; ship dashboards, traces and SLO alarms with the service; and set the scaling policy next to the budget alarm. Then the platform choice becomes an implementation detail rather than a lock-in.
